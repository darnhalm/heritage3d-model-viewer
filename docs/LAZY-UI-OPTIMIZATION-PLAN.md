# План ленивой загрузки интерфейса Model Viewer

Документ описывает поэтапное уменьшение стартового DOM, числа запросов и размера главного
JavaScript-бандла. Изменения должны сохранять текущее поведение редакторов, отладчика тайлов,
встроенных анимаций и embed-пресетов.

## Исходное состояние

Аудит выполнен на `BoxTextured.glb` после сборки production-бандла.

| Метрика | Полный viewer | Compact embed |
| --- | ---: | ---: |
| Всего DOM-узлов | 794 | 336 |
| Потомки закрытой левой панели | 410 | 0 |
| Потомки popup | 278 | 270 |
| Принудительные preload SVG | 40 | 0 |
| DOM таймлайнов | 0 | 0 |

Состав полного viewer:

- скрытое содержимое левой панели — 397 элементов;
- Info — 98 элементов;
- Measurement — 57 элементов;
- Fragment — 11 элементов;
- View & Share — 92 элемента;
- нижний видимый toolbar — около 15 элементов.

Главный `index.js` занимает около 660 КБ gzip, `style.css` — около 58 КБ gzip. Старый
Material Icons после отдельной оптимизации не загружается при обычном старте и подключается
только для внешнего хелпера с заданным `helper.icon`.

## Целевое состояние

| Метрика | Сейчас | Цель |
| --- | ---: | ---: |
| Полный стартовый DOM | 794 | не более 170 |
| Compact embed DOM | 336 | не более 100 |
| Preload SVG | 40 | 0 |
| Стартовые запросы SVG-иконок | около 43 | не более 10 |
| Скрытые popup-панели в DOM | 4 | 0 |
| Таймлайны при старте | 0 | 0 |
| Material Icons при старте | 0 | 0 |
| Главный JS | около 660 КБ gzip | ориентир 620–635 КБ gzip |

Цифры размера JS являются ориентиром, а не жёстким условием: общие зависимости React и PCUI
останутся в главном чанке. Приёмка выполняется по фактическим измерениям одной и той же модели
с очищенным кешем.

## Этап 0. Зафиксировать текущую базу

1. Запустить `npx tsc --noEmit`, `npm run lint`, `git diff --check` и `npm run build`.
2. Проверить, что `#material-icons-font` отсутствует на чистом старте.
3. Проверить, что stylesheet Material Icons появляется только после хелпера с `helper.icon`.
4. Проверить отсутствие `#poi-timeline-panel` и `#timeline-panel` при старте.
5. Закоммитить ленивую загрузку Material Icons отдельным коммитом:
   `Load legacy Material Icons on demand`.

## Этап 1. Автоматизировать стартовый аудит

Создать отдельный тест `tests/startup-performance.spec.ts`.

### Режимы проверки

1. Полный viewer с `BoxTextured.glb`.
2. `embed=1&ui=compact&autoplay=1`.
3. `embed=1&ui=none&autoplay=1`.

### Снимаемые показатели

- общее число DOM-узлов;
- число потомков `#panel-left`, `#scene-container` и `#popup`;
- наличие закрытых popup-панелей;
- число `link[rel="preload"]`;
- список загруженных JavaScript-чанков;
- количество запросов `/static/icons/`;
- наличие Material Icons, POI timeline и tile timeline;
- gzip-размер `index.js` и `style.css` после сборки.

Тесты должны использовать верхние границы, а не точное равенство количества элементов.
Небольшая правка кнопки или доступного текста не должна ломать performance-тест.

## Этап 2. Удалить общий preload 40 SVG

### Изменения

1. Удалить импорт `warmPanelIcons` из `src/index.tsx`.
2. Удалить вызов `warmPanelIcons()`.
3. Удалить `src/panel-icons.ts`, если он больше нигде не используется.
4. Не добавлять заменяющий общий preload.

Браузер должен загружать SVG естественно, когда соответствующий элемент появляется в DOM и
к нему применяется CSS.

### При старте могут загружаться

- Info;
- текущее состояние HD или SD;
- Measurement;
- View & Share;
- Fit;
- текущее состояние Orbit или Fly;
- Fullscreen;
- Fragment только для tileset.

Не должны заранее загружаться альтернативные состояния кнопок и иконки закрытых вкладок.

### Проверки

- спустя 3–4 секунды после старта нет `link[rel="preload"][as="image"]`;
- стартовых запросов `/static/icons/` не больше 8–10;
- нижние кнопки не мигают и имеют ожидаемые изображения;
- открытие каждой панели догружает нужные иконки без 404;
- повторное открытие использует кеш.

### Ожидаемый эффект

- исчезают 40 принудительных preload-запросов;
- с учётом необходимых видимых иконок чистое сокращение составит примерно 32–36 запросов;
- по ранее снятым данным исключается до 331 КБ исходных SVG, около 49 КБ при сжатии.

Коммит: `Load panel icons only when used`.

## Этап 3. Монтировать только активную popup-панель

Сначала изменить только жизненный цикл DOM, не вводя code splitting. Это отделяет ошибки
монтирования от возможных ошибок динамической загрузки.

### Изменения

В `src/ui/popup-panel/index.tsx` оставить `PopupButtonControls` постоянно смонтированным, а
вместо одновременного создания четырёх панелей выбирать только активную по `ui.active`:

- `info` → `InfoPanel`;
- `measurement` → `MeasurementsPanel`;
- `fragment` → `FragmentPanel`;
- `view` → `ViewPanel`;
- `null` → ни одной панели.

### Обязательные сценарии

- повторный клик по кнопке закрывает панель;
- клик вне popup закрывает панель;
- двойной клик по fragment box открывает Fragment через изменение `ui.active`;
- Measurement корректно завершает режим и удаляет свои обработчики;
- toolbar не меняет положение при открытии;
- мобильные ограничения остаются прежними;
- одновременно существует не больше одной popup-панели.

### Локальное состояние

`ViewPanel` содержит локальное состояние генератора embed-кода. До размонтирования нужно
разделить его поля:

- критичные пользовательские значения сохранить в observer или родительском компоненте;
- кратковременные флаги вроде `copied` можно сбрасывать;
- выбранный embed preset желательно сохранять в течение текущей сессии.

### Проверки

Для каждой панели проверить отсутствие на старте, появление по кнопке, отсутствие остальных
трёх панелей, удаление после закрытия и корректное повторное открытие без дублирования
обработчиков.

### Ожидаемый эффект

- закрытый `#popup` уменьшается примерно с 278 до 15–20 потомков;
- из стартового DOM удаляется около 258 элементов;
- compact embed уменьшается ориентировочно до 80–100 DOM-узлов;
- закрытые PCUI-контролы перестают участвовать в React reconciliation.

Коммит: `Mount popup panels only when opened`.

## Этап 4. Вынести popup-панели в динамические чанки

Условный render уменьшит DOM, но код панелей останется в `index.js`. После стабилизации
монтирования нужно разделить текущий `panels.tsx`:

```text
src/ui/popup-panel/
  index.tsx
  animation-controls.tsx
  info-panel.tsx
  measurements-panel.tsx
  fragment-panel.tsx
  view-panel.tsx
  shared.tsx
```

Каждая панель подключается через отдельный `React.lazy(() => import(...))`. Общие мелкие
компоненты помещаются в `shared.tsx`, чтобы Rollup не дублировал их в чанках.

### Suspense и ошибки

- fallback не должен двигать нижний toolbar;
- допустим пустой контейнер фиксированного размера или небольшой индикатор;
- ошибка загрузки чанка отображается локально и не ломает viewer;
- повторное открытие использует уже загруженный модуль.

### Проверки

- при старте нет чанков Info, Measurement, Fragment и View;
- открытие загружает только нужный чанк;
- повторное открытие не создаёт нового запроса;
- внешнее открытие Fragment работает до предварительного открытия popup.

Ориентировочный выигрыш главного JS: 15–25 КБ gzip.

Коммит: `Lazy-load popup panel modules`.

## Этап 5. Отделить оболочку левой панели от содержимого

### В стартовом DOM остаются

- `#panel-left`;
- логотип;
- `#panel-toggle`;
- минимальная resize-оболочка, если она действительно необходима до открытия.

До первого раскрытия не создаются вкладки, заголовок активной вкладки, Settings, Alignment,
Materials, POI, языки и Help.

### Явное состояние раскрытия

Состояние раскрытия нужно вынести из манипуляций CSS-классами в `panelExpanded` внутри
observer или корневого UI. Оно является сессионным и не сохраняется в settings-файл.

### Первая безопасная версия

`LeftPanel` подключается через `React.lazy` только после первого раскрытия. После первой
загрузки компонент можно оставить смонтированным до конца сессии и только скрывать. Это даёт
полный выигрыш стартовой загрузки без риска потерять локальное состояние редакторов.

### Вторая версия

Размонтировать содержимое при закрытии можно после переноса наружу следующего состояния:

- выбранная вкладка;
- активная карточка POI;
- временные save-индикаторы;
- alignment mode;
- незавершённые drag-операции;
- другие поля, которые должны переживать закрытие.

### Проверки

- на старте нет `.left-panel-tabs-container` и чанка `left-panel`;
- первое раскрытие загружает панель;
- Settings, Alignment, Materials и POI работают;
- закрытие не оставляет alignment или tile-debug активными;
- повторное открытие сохраняет необходимое состояние;
- resize и языковые кнопки не ломаются.

### Ожидаемый эффект

- из стартового DOM удаляется ещё около 397 элементов;
- полный viewer уменьшается ориентировочно до 130–170 DOM-узлов;
- код левой панели не участвует в стартовой загрузке и React-обновлениях до открытия.

Коммит: `Lazy-load left panel content`.

## Этап 6. Разделить вкладки левой панели

Дополнительный этап после стабилизации общей ленивой панели:

```text
src/ui/left-panel/
  shell.tsx
  settings-tab.tsx
  alignment-tab.tsx
  materials-tab.tsx
  poi-tab.tsx
```

Это позволит не загружать редактор POI при открытии Settings и не загружать тайловый debugger
до перехода в Materials. Каждая вкладка должна сохранять текущие правила выхода: Alignment
сбрасывает свой режим, Materials закрывает tile debug, POI удаляет timeline и наблюдателя.

Коммит: `Split left panel tabs into lazy modules`.

## Этап 7. Лениво создавать контроллеры и gizmo

DOM-оптимизация не затрагивает заранее создаваемые runtime-контроллеры. Их следует выносить
отдельными небольшими задачами:

1. `MeasurementController` — при первом включении Measurement.
2. `MicrophoneController` — при первом helper/microphone event.
3. `SelectionController` — при первом выборе.
4. Fragment gizmo — при открытии Fragment.
5. Alignment gizmo — при входе в Alignment.
6. `PoiController` — при включении POI или наличии POI в settings.

Для каждого контроллера нужен явный `ensure...Controller()`, безопасный `dispose()`, удаление
document-level обработчиков и тест повторного создания.

## Финальная приёмка

### Функциональные сценарии

- GLB без анимаций и GLB с анимациями;
- 3D Tiles;
- полный viewer, compact embed и minimal/none embed;
- desktop и mobile layout;
- все четыре popup-панели;
- Settings, Alignment, Materials и POI;
- POI timeline и tile replay timeline;
- Fragment, Measurement, View & Share;
- смена языка, fullscreen, HD/SD и Orbit/Fly.

### Обязательные технические проверки

- `npx tsc --noEmit`;
- `npm run lint`;
- `git diff --check`;
- `npm run build`;
- существующие smoke и tile tests;
- новый стартовый performance-тест;
- визуальная проверка полного viewer и compact embed;
- сравнение ресурсов и DOM с базовыми цифрами этого документа.

## Рекомендуемый порядок коммитов

1. `Load legacy Material Icons on demand`
2. `Add startup UI performance assertions`
3. `Load panel icons only when used`
4. `Mount popup panels only when opened`
5. `Lazy-load popup panel modules`
6. `Lazy-load left panel content`
7. `Split left panel tabs into lazy modules`
8. Отдельный коммит для каждого runtime-контроллера и gizmo

Такой порядок позволяет измерять эффект каждого изменения, локализовать регрессии и не
смешивать DOM-оптимизацию с изменением жизненного цикла инструментов.
