# Тайлы для сплатов: `make-lod.sh` и быстрое действие Finder

Инструмент готовит из обычного сплата **тайловую (Streamed SOG) сцену** и заливает её в
Object Storage. Нужен потому, что монолитную сцену браузер качает и распаковывает целиком:
у сцены на 8.24 млн сплатов (108 МБ `.sog`) это ~50 секунд до первого кадра и все сплаты
в памяти, а глобальный бюджет `splatBudget` на такую сцену не действует — он ограничивает
только octree/LOD-сцены.

Во вьюере ничего включать не надо: стриминг активируется самим фактом загрузки
`lod-meta.json` в gsplat-компонент.

## Установка быстрого действия

```bash
scripts/install-quick-action.sh          # поставить
scripts/install-quick-action.sh --remove # убрать
```

После этого: правый клик по `.sog` / `.ply` в Finder → **Быстрые действия** →
«Heritage3D: Make LOD». Откроется Terminal с прогрессом — уведомления macOS не умеют
показывать прогресс-бар, поэтому окно терминала здесь и нужно.

Путь к скрипту прописывается в действие при установке. Если репозиторий переехал —
запустите установку заново.

## Из терминала

```bash
scripts/make-lod.sh "path/to/[See the World] Sacrario Militare di Oslavia.sog"
```

Что происходит:

1. **Прореживание.** `splat-transform` делает уровни детализации из источника
   (по умолчанию 50%, 25%, 10%) в промежуточные PLY. Прореживание обязано быть последним
   действием вызова и писать `.ply`, поэтому уровни готовятся отдельными запусками.
2. **Сборка тайлов.** Второй проход собирает уровни (`-l 0..3`) в `lod-meta.json` + тайлы.
3. **Заливка.** `yc storage s3 cp --recursive` (или `rclone`, если установлен) кладёт папку
   в `s3://<бакет>/<префикс>/<имя>-lod/`.
4. Ссылка на вьюер копируется в буфер обмена.

Имя сцены приводится к slug — пробелы и скобки в `?load=` пришлось бы кодировать дважды
(`%2520`), и ссылка становится нечитаемой. Кириллица транслитерируется, иначе от русского
названия не осталось бы ничего и разные сцены схлопнулись бы в одно имя:

| Файл | Папка в бакете |
|---|---|
| `[See the World] Sacrario Militare di Oslavia.sog` | `see-the-world-sacrario-militare-di-oslavia-lod` |
| `Сакрарий Ославия (2024).sog` | `sakrariy-oslaviya-2024-lod` |
| `Ёлка на Щёлковском шоссе.ply` | `elka-na-schelkovskom-shosse-lod` |
| `scene.compressed.ply` | `scene-lod` |

Если слаг всё-таки совпал с уже существующей в бакете сценой, скрипт **откажется работать**:
затирать чужие тайлы молча нельзя. Перезапись — только явным `FORCE=1`.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `VIEWER_BUCKET` | `playcanvasviewer` | бакет |
| `VIEWER_PREFIX` | `models` | префикс в бакете |
| `VIEWER_URL` | `https://playcanvasviewer.website.yandexcloud.net` | адрес вьюера для ссылки |
| `LOD_LEVELS` | `50% 25% 10%` | доли прореживания; больше уровней — плавнее переходы |
| `FILTER_HARMONICS` | — | `0..3`, обрезать сферические гармоники |
| `LOD_CHUNK_COUNT` | — | гауссиан на тайл, в тысячах (по умолчанию 512 решает splat-transform) |
| `SPLAT_TRANSFORM_VER` | `3.1.7` | версия инструмента (тянется через `npx`) |
| `DRY_RUN=1` | — | всё сконвертировать, но не заливать |
| `KEEP_TEMP=1` | — | не удалять промежуточные файлы |
| `FORCE=1` | — | перезаписать сцену, если такая папка в бакете уже есть |

Требуется: Node.js (`npx`), `python3` (слаг с транслитерацией), `yc` CLI с активным
профилем или `rclone`.

## Место на диске

Промежуточные PLY пишутся несжатыми. Со сферическими гармониками это ~15–20× от размера
`.sog`, поэтому скрипт заранее проверяет свободное место и отказывается стартовать, если
его мало. Для сцены Ославии (108 МБ, гармоники есть — в архиве лежат `shN_centroids.webp`
и `shN_labels.webp`) это порядка **1.6 ГБ**.

`FILTER_HARMONICS=0` убирает старшие гармоники: промежуточные файлы становятся примерно
вчетверо меньше, самая дорогая по CPU часть (палитризация SH) исчезает, итоговая сцена
теряет ~40% объёма — ценой блеска и зеркальных отражений, зависящих от угла взгляда.
В референсной LOD-сцене PlayCanvas старших гармоник нет, только `sh0`.

## Прогресс

- **Конвертация** — прогресс по этапам: номер этапа, спиннер, время. Долю внутри этапа
  `splat-transform` не сообщает, поэтому бар внутри этапа не двигается: врать не хочется.
- **Заливка** — честный процент: и `yc`, и `rclone` печатают строку на каждый файл, а общее
  число файлов уже известно после конвертации.

Подробный лог: `~/Library/Logs/heritage3d-make-lod.log`.

## Ограничения

- Токен `yc` истекает. Если это случится, CLI попытается открыть браузер для повторной
  авторизации — из быстрого действия это выглядит неожиданно. Для регулярной работы лучше
  завести сервисный аккаунт или делать заливку в CI.
- `npx` при первом запуске скачивает `@playcanvas/splat-transform` (~4.5 МБ) и кэширует его.
- Тайлов получается порядка 200–300 файлов на сцену вашего размера (по 6 файлов на тайл:
  `meta.json` + `means_l/means_u/scales/quats/sh0`). Это нормально — заливка идёт одной
  командой, а количество объектов не влияет на скорость показа.

## Альтернатива без локальной машины

Ту же цепочку можно выполнять в CI: раннер скачивает исходник из бакета, конвертирует и
заливает результат обратно — ваш интернет не участвует, ключи уже лежат в секретах
(`YC_S3_KEY_ID` / `YC_S3_SECRET`, ими пользуется `scripts/deploy-viewer.py`). Осторожно с
диском раннера: полтора гигабайта промежуточных файлов там может не хватить, помогает
`FILTER_HARMONICS=0` или `--scratch-dir`.

# Состояние работы (для продолжения с чистого листа)

Раздел-передача: что сделано, что проверено, где грабли. Обновляйте по мере работы.

## Файлы

| Файл | Роль |
|---|---|
| `scripts/make-lod.sh` | вся логика: прореживание → сборка тайлов → заливка → ссылка |
| `scripts/install-quick-action.sh` | генерирует Automator-бандл в `~/Library/Services`, путь к скрипту вшивается при установке |
| `docs/MAKE-LOD.md` | этот файл |

Быстрое действие — тонкая обёртка: открывает Terminal и запускает `make-lod.sh`. Вся
отладка делается напрямую скриптом, действие переставлять не нужно (кроме случая, когда
репозиторий переехал).

## Что проверено

- синтаксис обоих скриптов (`bash -n`), пути ошибок (нет файла, неподдерживаемый формат);
- отрисовка бара на 0/25/50/75/100 %, переходы между этапами, перехват падения этапа;
- спиннер на штатном macOS bash 3.2 — кадры лежат в массиве, потому что строку bash режет
  по байтам и многобайтовый символ разваливается;
- слаг на реальных именах: латиница со скобками и пробелами, кириллица, диакритика,
  «!!!» → fallback `scene`;
- механика защиты от перезаписи: 200 на существующий `lod-meta.json` → отказ, 404 → работаем;
- `yc storage s3 cp --recursive --dryrun` — структура подпапок сохраняется;
- служба зарегистрирована системой (видна в `pbs -dump` с контекстом Finder);
- экранирование имени с пробелами и скобками при передаче в Terminal (`printf %q`) и
  уникальность временных файлов при повторных запусках.

## Что НЕ проверено

- **сама конвертация: `splat-transform` ни разу не запускался.** Нужен доступ в сеть, чтобы
  `npx` скачал пакет (~4.5 МБ). Соответственно не проверены: реальные флаги прореживания,
  формат вывода инструмента, время и потребление памяти, число получившихся тайлов;
- клик по пункту в Finder (только регистрация службы);
- заливка по-настоящему (только `--dryrun`);
- ветка `rclone` (на машине его нет, поэтому всегда идёт ветка `yc`).

**Первый шаг для проверки — дешёвый:** маленькая публичная сцена и без заливки.

```bash
curl -O https://raw.githubusercontent.com/playcanvas/engine/main/examples/assets/splats/guitar.compressed.ply
DRY_RUN=1 KEEP_TEMP=1 scripts/make-lod.sh guitar.compressed.ply
```

90 тыс. сплатов, 1.5 МБ — быстро, и сразу видно, что печатает инструмент, сколько выходит
тайлов и файлов. Потом можно на своей сцене.

## Известные грабли и открытые вопросы

- **Токен `yc` истекает.** Тогда CLI пытается открыть браузер — из быстрого действия
  выглядит неожиданно. Варианты: сервисный аккаунт или заливка в CI.
- **Уровни детализации зашиты** как `50% 25% 10%` (`LOD_LEVELS`). Оптимальные доли и число
  уровней под ваши сцены не подбирались.
- **`--lod-chunk-count` / `--lod-chunk-extent` не трогали** — работают дефолты
  splat-transform (512 тыс. гауссиан и 16 м на тайл). Крупнее тайлы = меньше файлов, но
  грубее стриминг.
- **Фоновый сплат (`-l -1`, окружение)** скрипт не поддерживает: `lod-meta.json` умеет
  ссылаться на отдельный `environment`, у нас такой вход не предусмотрен.
- **Версия инструмента прибита** — `SPLAT_TRANSFORM_VER=3.1.7`. Обновлять осознанно: флаги
  LOD у него менялись.
- **Прогресс внутри этапа конвертации не двигается** — инструмент долю не сообщает. Если в
  его выводе найдутся проценты, бар можно сделать честным и там.

## Контекст, который не нужно выводить заново

- Движок в проекте — **playcanvas 2.20.6**. Стриминг включается **самим фактом** загрузки
  `lod-meta.json` в gsplat-компонент, настроек во вьюере не требуется.
- `splatBudget` (у нас 3 млн, ставится в `Viewer.initGSplat`) ограничивает **только**
  octree/LOD-сцены — у монолитной сцены он не действует, это проверено в движке
  (`GSplatWorld._enforceBudget` обходит `_octreeInstances`).
- Структура `lod-meta.json`: `lodLevels`, `filenames` (тайлы вида `<уровень>_<номер>/meta.json`),
  `tree` (габариты + потомки), опционально `environment`. Каждый тайл — маленький SOG:
  `meta.json` + `means_l/means_u/scales/quats/sh0` (+ `shN`, если гармоники не обрезаны).
- Вьюер на проде **уже проверен на LOD-сценах**: 7 уровней, догрузка чанков при приближении
  камеры, `frame:request` срабатывает, на `?webgl` тоже работает.
- Тестовые LOD-сцены PlayCanvas (CORS открыт, годятся для проверки вьюера):
  `https://code.playcanvas.com/examples_data/example_roman_parish_02/lod-meta.json`,
  `.../example_skatepark_02/lod-meta.json`.
- Ваша сцена в бакете: `models/[See the World] Sacrario Militare di Oslavia.sog`,
  8 242 276 сплатов, 108 МБ, гармоники **есть** (`shN_centroids.webp`, `shN_labels.webp`),
  ~46 с до первого кадра на WebGPU.
- Документация PlayCanvas: [Generating Streamed SOG](https://developer.playcanvas.com/user-manual/splat-transform/streamed-sog/),
  [LOD Streaming](https://developer.playcanvas.com/user-manual/gaussian-splatting/building/lod-streaming/),
  [splat-transform](https://github.com/playcanvas/splat-transform).
- Готового инструмента с «нарезать + залить» не существует: браузерный
  [SuperSplat Convert](https://superspl.at/convert) отдаёт только `.ply / .compressed.ply /
  .sog / .csv / .html / .voxel.zip`, LOD там нет; редактор SuperSplat экспортирует
  `ply / splat / sog / spz / viewer` — тоже без LOD. `lod-meta.json` пишет только CLI.
