## Постэффекты — 14 сентября 2026

TAA и MSAA доступны и взаимоисключаются. CameraFrame использует RGBA16F для HDR-сцены. SSAO для Unlit применяется на этапе композиции (визуальное затемнение; не физическое освещение и не изменение материала). EASU и RCAS работают после преобразования для экрана; RCAS использует относительный потолок по локальному HDR-максимуму, сохраняя значения выше единицы. Временное накопление неподвижных кадров из Multiframe по-прежнему выключено в HDR; вместо него доступны TAA/MSAA.

CameraFrame 2.21.4 кодирует результат композиции гаммой 2.2 даже в FP16. HdrOutput учитывает это только для его результата и восстанавливает линейные значения перед экспозицией. Этот промежуточный проход не обрезает HDR, но добавляет округление FP16. Экспорты SDR используют те же экспозицию, LUT и резкость.

Поддерживается обычная горизонтальная SDR LUT PNG/WebP, как в существующем редакторе. Для HDR-пути размер таблицы берётся из изображения (N² × N); таблица применяется после SDR mapping в координатах sRGB. На HDR-мониторе при включённом HDR LUT обходится: источник и загруженная таблица остаются, переключение в SDR снова включает LUT. Это не поддержка Log/HDR LUT; их цветовое пространство и диапазон требуют отдельного описания.

Tonemap при HDR фиксирован в UI как Linear: HDR-вывод сохраняет расширенный диапазон, SDR-просмотр использует существующий Reinhard. Общая экспозиция находится в Post-processing и действует на собранный HDR-кадр, включая видимое окружение. Прежний skybox.exposure переименован в UI в «Яркость окружения (EV)»; это интенсивность HDRI, она не должна подменять экспозицию камеры. Без калибровки исходников одинаковые EV не означают физически согласованные HDRI/EXR.

Final Render явно показывает Unlit / Lit (PBR). **Person003 был намеренно подготовлен как Unlit для первого теста HDR.** Плеер не переводит новые модели в Unlit по имени, числу карт или факту наличия HDR. Встроенные HDR-привязки v1 поддерживают Unlit и Lit/PBR, сохраняя тип из GLB.

# HDR surface, v1

HDR-представление поверхности подключается отдельно к одному GLB с Unlit и/или Lit/PBR материалами. Исходный GLB и его текстуры остаются доступными; обычная загрузка GLB не активирует HDR, не загружает Khronos WASM и не создаёт HDR-буфер сцены.

## Встроенный HDR в GLB (13 сентября 2026)

Рабочий пользовательский путь теперь — **один GLB**. Кнопка загрузки внешней HDR-поверхности удалена, `?surface=` больше не загружает JSON. Внутренний `loadHdrSurface` сохранён только для численных тестов/benchmark старого конвейера. Встраивание готовой текстуры:

```sh
node scripts/embed-hdr-glb.cjs model.glb surface.ktx2 model-hdr.glb 0
```

Плеер открывает `?webgpu&load=model-hdr.glb` или локально перетаскиваемый GLB. Геометрия, исходные карты и HDR находятся в одном BIN chunk; SDR-карта сохраняется для остальных читателей. Упаковщик не меняет исходный GLB и не перезаписывает существующий результат.

**Это частное соглашение HERITAGE3D, не стандартный HDR в KHR_texture_basisu.** Ратифицированное расширение требует LDR UASTC и sRGB transfer для цветовых карт. Поэтому HDR хранится отдельным bufferView с метаданными `extras.HERITAGE3D_hdr_surface`:

```json
{
  "version": 1,
  "format": "uastc-hdr-ktx2",
  "colorSpace": "linear-srgb",
  "range": "hdr",
  "textures": [
    { "material": 0, "bufferView": 12, "width": 4096, "height": 4096 }
  ]
}
```

Неизвестные читатели видят обычную встроенную SDR Base Color. Пересохранение сторонним редактором может удалить частные extras/неиспользуемый bufferView; сохранность HDR при таком round-trip не гарантируется. Упаковщик сохраняет остальные карты без распаковки и перекодирования.

HDR canvas теперь запрашивается после загрузки HDR-карты. Проверяются `rgba16float` и `toneMapping: extended`, при отказе браузера остаётся SDR. При удалении HDR-модели восстанавливается исходная конфигурация canvas. Изменение возможностей монитора обрабатывается без `surface`-параметра; физический вывод всё ещё требует проверки на HDR-мониторе. Адаптер привязан к PlayCanvas 2.21.4.

В интерфейсе выключенный HDR перечёркнут; доступность кнопки отдельно определяется возможностями браузера. Метка HDR находится у **Base Color**, рядом с KTX2, а не у Final Render. Для явно Unlit материала внутренний emissiveMap трактуется как Base Color; единственная diffuse-карта сама по себе не превращает PBR в Unlit. В Lit/PBR HDR-карта подключается к diffuseMap (Base Color) и участвует в освещении; emissiveMap остаётся исходной. Панель поддерживает экспозицию, TAA/MSAA, SSAO, EASU и RCAS; обычный SDR LUT действует только в SDR-просмотре.

## Blender: проверка установленного плагина

Проверен установленный `gltf_ktx2_texture_extension` **1.0.7** для Blender 5.2: `ktx_tools.py` закрепляет KTX-Software **4.4.2**, режимы карт — ETC1S/обычный UASTC, промежуточные изображения пишутся в PNG. Готового экспорта **UASTC HDR** для карт материала нет. Переключение Gamma → Linear не добавляет HDR.

Чтобы добавить такой экспорт, нужны отдельный режим UASTC HDR, KTX-Software с HDR encoder (в нашем прототипе 5.0.0-rc2), получение исходных float-пикселей через EXR без PNG/тонального преобразования, явное приведение primaries/transfer, линейные mip-уровни и упаковка HDR в указанное частное соглашение. Unlit должен экспортироваться как `KHR_materials_unlit` с `baseColorTexture`. Установленный плагин этим изменением не модифицировался.

Источники: [KHR_texture_basisu](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_texture_basisu/README.md), [glTF-KTX-texture](https://github.com/tonis2/glTF-KTX-texture), [KTX release notes](https://github.com/KhronosGroup/KTX-Software/blob/main/RELEASE_NOTES.md).

Текущая реализация относится к 2D-карте поверхности. HDRI окружения (world/skybox, кубическая карта) — отдельная задача и этим соглашением не поддерживается.

## Ограничения данных

`material` — индекс материала в исходном GLB, начиная с нуля. Материал должен использоваться в текущей сцене, иметь текстуру base color. Сохраняются UV-преобразования, множители материала и исходный путь прозрачности. HDR подменяет diffuseMap у Lit/PBR или emissiveMap, через которую PlayCanvas реализует цвет Unlit. Нормали, metalness/roughness, эмиссия Lit и alpha остаются исходными; HDR-привязка заменяет только RGB Base Color, исходная карта прозрачности сохраняется. Значения HDR выше 1 технически сохраняются, но сами по себе не означают физически калиброванную отражательную способность PBR. Переключение варианта материала снимает HDR-подмену; слои/варианты HDR — следующий этап.

Поддерживаются до 16 привязок, полная mip-цепочка и размеры до ограничения GPU, максимум 8192 по оси. Суммарный бюджет **256 MiB в эквиваленте RGBA16F с mip-уровнями** действует и для сжатого источника, чтобы гарантировать запасной путь. Поэтому квадратная 8K-текстура сейчас не проходит бюджет; 4K занимает около 170.67 MiB в RGBA16F, 21.33 MiB в BC6H. Это бюджет полезных данных, а не предел всей памяти процесса: декодер, копии, исходные GLB-текстуры и буферы рендера требуют дополнительную память.

## KTX2 HDR

Штатный Basis loader PlayCanvas 2.21.4 не расширен. `ktx2.ts` проверяет контейнер и запускает отдельный Worker с закреплённым Khronos `libktx_read` **v5.0.0-rc2**. Версия предварительная; источник, контрольные суммы и лицензии находятся в `static/lib/ktx-hdr/`.

Worker принимает UASTC HDR 4×4 и 6×6, linear transfer, BT.709/sRGB primaries, ориентацию right/down. BC6H Unsigned используется при наличии соответствующей возможности GPU, иначе RGBA16F. Для диагностики manifest допускает `"transcodeTarget": "rgba16f"`. ASTC HDR пока не используется: существующий ASTC-формат этого движка относится к LDR. LDR KTX2, premultiplied color, KTXmapRange и нестандартный swizzle отклоняются вместо незаметного изменения цвета. Рендер требует фильтруемые и доступные для рендера FP16-текстуры.

Пример подготовки **уже приведённого к линейным sRGB/BT.709 primaries** EXR официальным CLI KTX-Software v5.0.0-rc2:

```sh
ktx create --format R16G16B16A16_SFLOAT --encode uastc-hdr-4x4 \
  --generate-mipmap --mipmap-filter box --assign-tf linear --assign-primaries bt709 \
  --assign-texcoord-origin top-left surface.exr surface.ktx2
```

`--assign-*` описывает подготовленные данные; это не преобразование произвольного ICC/ACES-профиля. UASTC HDR/BC6H — представление с потерями, не архивный цифровой негатив. EXR/TIFF и проект реконструкции нужно сохранять отдельно.

## Несжатый FP16 и EXR/TIFF

Альтернативный manifest использует `"format": "rgba16f-le"` и URI `.bin`. Payload — плотно упакованные little-endian RGBA float16, все mip-уровни от полного размера до 1×1. RGB конечный и неотрицательный, alpha в [0,1]. Цвет линейный, primaries sRGB/D65.

```sh
python3 -m venv .venv-hdr
.venv-hdr/bin/pip install numpy==2.0.2 tifffile==2024.8.30 OpenEXR==3.4.15
.venv-hdr/bin/python scripts/pack-hdr-surface.py surface.exr \
  --output output/surface --material 0 --transfer linear
```

Пакер проверен с указанными версиями. Принимает односоставной RGB/RGBA EXR и interleaved RGB/RGBA TIFF; только непрозрачный вход и размеры степени двойки. Для uint8/uint16 выполняет нормирование; float сохраняет. `--transfer srgb` явно линеаризует вход. Профили ICC, ACES и неизвестные primaries необходимо преобразовать заранее. Пакер не исправляет отрицательные значения и переполнение FP16 молча. Создаёт mip-уровни линейным box-фильтром, manifest, бинарный файл и provenance с SHA-256 оригинала и результата, не изменяя оригинал.

## Экспозиция, SDR и HDR-дисплей

Сцена рендерится в RGBA16F без gamma/tone mapping камеры. Один выходной проход применяет экспозицию `2^EV`, затем для SDR — luminance Reinhard с нормированием превышающих единицу компонент; далее кодирует sRGB. Для HDR тональное сжатие пропускается, сохраняются значения выше 1. Primaries остаются sRGB, расширенный gamut P3 не реализован. PNG/обложки получают SDR-представление.

Экспозиция ±16 EV находится в «Постэффектах». Интенсивность окружения `skybox.exposure` сохраняет прежнее назначение. TAA/MSAA, SSAO и EASU/RCAS подключены с 14 сентября; SDR LUT действует в SDR-просмотре. Накопительное сглаживание отключено в HDR. После снятия HDR обычный путь восстанавливается. HD/SD продолжает управлять разрешением рендера.

Метка **HDR** означает источник; кнопка **HDR** рядом с HD/SD означает вывод. Выключение кнопки включает SDR preview, сохраняя HDR-текстуру и экспозицию.

## План распространения Blender-расширения

Требование пользователя от 2026-09-14: возможность распространения предусмотреть до разработки аддона. Ниже проектные требования, а не уже реализованный релиз.

- Собственный extension ID, название и версии; не перезаписывать установленный `gltf_ktx2_texture_extension`. При использовании его кода сохранить атрибуцию upstream и явно обозначить изменения. Установленная версия 1.0.7 содержит Apache-2.0 в LICENSE и manifest.
- Первоначальный канал: ZIP-релизы расширения и исходники через собственный репозиторий/сайт. Официальный Blender Extensions — отдельная цель после проверки актуальных требований к лицензии, внешним исполняемым файлам и сети; публикация туда не обещана.
- Рекомендуемая лицензия нового аддона: GPL-3.0-or-later для совместимости с требованиями официального каталога; Apache-уведомления заимствованных компонентов сохраняются. Финальный перечень лицензий определяется по реально включённым исходникам и бинарникам.
- KTX CLI — отдельный процесс, закреплённая проверенная версия, источник сборки и SHA-256. Не полагаться на системный PATH, /tmp, Node.js, npm или вручную установленный KTX. Перенести упаковку GLB в переносимый модуль Python, доступный из Blender.
- Целевые платформы: Windows x64, macOS arm64/x64, Linux x64; включать платформу в список поддерживаемых только после сборки и теста установки/экспорта. Проверить зависимости бинарников и подписание/notarization для macOS.
- Предпочтительный прямой дистрибутив — отдельный ZIP под платформу с кодировщиком и его зависимостями для работы без сети.
