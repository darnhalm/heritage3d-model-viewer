# Проверка CVD-профилей в viewport

Дата проверки: **2 ноября 2026 года**.

Этот документ фиксирует ручную визуальную проверку LUT в HERITAGE3D Viewer и
связанный с ней автоматический тест интерфейса. Это инженерная проверка
интеграции, а не исследование восприятия с участием людей.

## Конфигурация

- сборка: локальный `dist`, собранный командой `npm run build`;
- сцена: `models/3d-tiles/Kronstadt_Naval_Cathedral/tileset.json`;
- язык интерфейса: русский;
- раздел: **Настройки → Постобработка → Профиль CVD**;
- сила LUT: `1`;
- сравниваемые состояния: «Без профиля», «Дейтеранопия — сим.» и
  «Дейтеранопия — комп.»;
- полный viewport браузера: 1666 × 1251 px; при открытой левой панели область
  сцены занимала приблизительно 1356 × 1251 px.

Прямая ссылка для воспроизведения на локальном сервере:

```text
/?load=models%2F3d-tiles%2FKronstadt_Naval_Cathedral%2Ftileset.json&lang=ru
```

## Результат ручной проверки

| Проверка | Ожидаемое поведение | Наблюдение | Результат |
|---|---|---|---|
| Список профилей | Один список, назначение указано коротким суффиксом | Видны варианты `— комп.` и `— сим.` без дополнительных переключателей | пройдено |
| «Без профиля» | LUT отсутствует | Исходные цвета сцены восстановлены | пройдено |
| «Дейтеранопия — сим.» | Снижается различимость красно-зелёных оттенков, нейтральные поверхности существенно не окрашиваются | Зелень и золото смещаются к жёлто-оливковым оттенкам; белый камень остаётся визуально нейтральным | пройдено |
| «Дейтеранопия — комп.» | Более слабое преобразование, часть цветового различия переносится в светлоту | Изменение заметно слабее симуляции; насыщенные участки немного меняют яркость и оттенок | пройдено |
| Переключение профилей | Выбранный PNG загружается лениво и применяется без перезагрузки сцены | Имя активной LUT меняется на выбранный файл, сцена обновляется сразу | пройдено |
| Очистка | Выбор «Без профиля» удаляет активную LUT | `camera.colorLutName` становится пустым | пройдено |

Небольшой зеленовато-оливковый сдвиг на растительности и позолоте признан
ожидаемым для симуляции дейтеранопии. Он не является равномерным зелёным
фильтром: на нейтральной оси LUT значения каналов R, G и B остаются равными,
включая чёрный `[0, 0, 0]` и белый `[255, 255, 255]`.

Сцена собора преимущественно состоит из белых и серых поверхностей, поэтому она
хорошо обнаруживает нежелательную окраску нейтралей, но плохо показывает
различимость насыщенных красно-зелёных пар. Для оценки палитр следует
дополнительно использовать `demo-chart.png`.

## Автоматическая проверка интерфейса

Тест [`tests/color-vision-lut.spec.ts`](../../tests/color-vision-lut.spec.ts)
проверяет тот же пользовательский путь:

1. открывает панель;
2. выбирает «Протанопия — сим.» и проверяет файл активной LUT;
3. выбирает «Дейтеранопия — комп.» и снова проверяет файл и подпись;
4. выбирает «Без профиля» и проверяет очистку LUT.

Команда:

```sh
npx playwright test tests/color-vision-lut.spec.ts --timeout=60000
```

Результат последнего запуска: **1 тест пройден за 18,8 с**. Дополнительно
`npm run lint` завершился без ошибок, а все 14 PNG из `manifest.json` были
прочитаны как RGB-изображения размером 256 × 16. В интерфейс выводятся 13
профилей; служебный `cvd-neutral` в список не включён.

## Что эта проверка не доказывает

- Она не подтверждает клиническую или поведенческую эффективность коррекции.
- Она не воспроизводит зрение конкретного человека: симуляция описывает
  усреднённую модель.
- Монитор, цветовой профиль ОС и условия освещения не калибровались.
- Текущие протан- и дейтеран-коррекции попарно совпадают по пикселям внутри
  одинаковой степени тяжести. Разные названия в данном случае не означают разные
  преобразования.
- Для решения о выпуске коррекции нужны задания на различение цветов и проверка
  с реальными protan-, deutan- и tritan-пользователями.
